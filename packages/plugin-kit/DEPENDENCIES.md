# Capability dependencies

The plugin contains instructions and bundled resources. Installing it does not install runtimes, authenticate services, or enable external writes. Check the current project's dependencies and the Host's callable tools before deciding a dependency is missing; absence of a global executable on PATH is not sufficient. Reuse the user's authorization for necessary local setup. Missing remote credentials must not stop independent local work.

Host-owned document, spreadsheet, presentation, PDF, image and browser tools remain Host dependencies. They are not silently forked or supplied by this plugin. Inspect current availability rather than assuming an old tool name still exists. If an equivalent Host tool is available, use it only after checking the required function, output and verification coverage.

## Data and output locations

Planning files belong to the selected project. Credentials remain in the service/Host credential store. Private learning corpora stay in user-approved locations. Kami output/cache and mutable templates belong outside the plugin; preserve relative assets or update their paths when copying a template. The plugin cache may be replaced during upgrade and is not a durable data store.

Kami's HTML templates use bundled local font files without a network fallback. If publishing a web page from a template, include its referenced assets and measure the resulting transfer size: the bundled TrueType fonts can be larger than the former remote WOFF2 references. Visual rendering in a local offline check is not a site performance measurement.

## Acceptance boundaries

A found skill is not proof of correct triggering. A successful local check is not proof of authentication, deployment or production behavior. Validate the requested task and report the relevant limit. Public redistribution is separately governed by LICENSES.json. Use MIGRATION.md for project enablement, managed legacy retirement and recovery.
