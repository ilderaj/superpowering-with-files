# Product

## Register

product

## Users

Primary users are developers, workflow maintainers, and tool builders who already work with coding agents or are evaluating how to make those workflows safer and more repeatable. They arrive with technical context and want to quickly judge whether this harness fits into real engineering practice rather than a demo-only environment.

## Product Purpose

superpowering-with-files provides a governance layer for local and cloud coding-agent workflows. It makes planning state durable, projects one policy into multiple agent surfaces, and keeps verification and release lanes explicit. Success means a technically literate visitor understands within the first few sections what the harness is, why it is more reliable than ad hoc scripts, and where to go next for the real implementation.

The current V1.3 direction extends this purpose to the Owner's broader work only where the existing Host and office capability can support it: preserve useful context through interruption, keep scope and authorization explicit, and expose verifiable delivery boundaries. This is a current-workspace direction, not a market-size or universal cross-Host claim.

## Brand Personality

Precise, durable, opinionated.

The voice should feel structured and engineering-led without becoming cold or bureaucratic. It should communicate confidence through specificity, not through hype or abstract AI language.

## Anti-references

- Generic AI landing pages built from vague promises, gradient-heavy futurism, or neon-on-black spectacle.
- Enterprise dashboard cosplay that explains the project through fake metrics, fake admin panels, or generic product chrome.
- Marketing pages that rely on interchangeable feature cards and slogans instead of showing the operating model.

## Design Principles

- Practice what you preach. The interface should model order, continuity, and explicit structure.
- Explain before you persuade. Visitors should understand the system before being asked to adopt it.
- Show the operating model, not slogans. Real workflow structure should carry the message.
- Earn trust through specificity. Concrete terminology and real boundaries are more persuasive than broad claims.
- Keep the path to source visible. The project should always feel close to the repository and documentation, not separated from them.

## Accessibility & Inclusion

Target WCAG AA as the default baseline. Support reduced motion, avoid conveying critical meaning through color alone, and preserve readable structure across desktop and mobile layouts.
