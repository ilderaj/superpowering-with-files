# Trio V2 Cutover

Codex is the only managed Trio target. Generic targets remain manual.

The V2 public command surface advertises exactly seven commands: `install`, `sync`, `doctor`, `trio`, `verify`, `checkpoint`, and `token-audit`. The dispatcher still retains V1 compatibility handlers for existing callers, but they are not part of the advertised V2 command surface. This is a compatibility boundary, not a claim that legacy handlers were deleted.

Normal `sync` supports only `--dry-run` and `--check` and has no takeover or conflict flags. The narrowly scoped V2 path that may take over an unowned user-global ChiefOps destination is `./scripts/harness install --takeover-chiefops`, which is restricted to an existing schema-v2 `user-global` state with exactly one enabled managed Codex placement, ownership of exactly the five core Trio surfaces, and exactly one unowned ChiefOps destination. Generic/manual targets are preserved and never written. Ordinary `install` remains workspace-only.

Before writing, the takeover captures and revalidates the complete bounded preimage set (six primary entries, five supporting references including explicit absence, and the prior V2 state); each capture is `lstat → read → lstat` and requires exact file and parent dev/ino/nlink identities before and after the read, so a replacement between the stat and the read fails closed with `ERR_TRIO_PREIMAGE_DRIFT` before any backup or apply write. It then publishes a unique, read-back-verified immutable backup at `<authorityRoot>/.harness-backup/trio-takeover/<id>/`. Before any backup write, every existing backup-root ancestor from the authority root through `.harness-backup/trio-takeover` must be a real, non-symlink directory physically contained under the authority root; a symlinked or escaping ancestor fails closed with `ERR_TRIO_PHYSICAL_GATE` and no state or target change. The manifest preserves the pre-takeover `ownership.source`/`manifestRef`/entries and the prior recovery `checkpointRef` and `rollbackRef` unchanged. The settled state preserves `ownership.source`, `ownership.manifestRef`, and `recovery.checkpointRef`, adds ownership for ChiefOps and newly created references, and sets `recovery.rollbackRef` to a parseable `trio-backup-v1:<absolute manifest path>:<sha256>` file reference whose digest is derived from the manifest file bytes as written and re-read (verification recomputes sha256 over the manifest file and compares). Every write is bound to the backup preimages so same-content inode replacement fails closed and mid-apply failures compensate back to the preimages.

The takeover must run from the durable authority root (the checkout that owns `.harness/state.json`), never from a transient worktree, and only with applicable human authorization. It never merges, pushes, or auto-adopts; verify afterwards with `sync --check` and `doctor --check-only`.

The projection contract does not provide cross-authority-root serialization. It does not provide multi-file atomic visibility. It does not provide crash, SIGKILL, or power-loss atomicity. It does not provide automatic residue cleanup. Ownership and recovery records remain the evidence required for any separately authorized repair or cleanup.

Supporting references use the same owned-update and physical-path checks as primary entries. Missing references are created on ordinary sync when upgrading a six-entry installation. Existing unmanaged reference files are conflicts; takeover never absorbs them implicitly. References add files, not skill identities or durable task-state authorities.
