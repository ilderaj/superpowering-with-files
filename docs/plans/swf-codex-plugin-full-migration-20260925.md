# SWF Codex 插件完整迁移与验收方案

状态：设计候选，未执行运行环境切换。范围仅含 Codex、`~/.codex`、`~/.agents`、SWF 项目，以及完整插件的私有构建与分发；不迁移 Claude、Cursor 或其他 IDE 的配置。任务数据、MCP 凭据、Host 自有技能和外部服务不属于插件包。

## 完成定义与已知基线

“完整迁移”指日常 Codex 会话只通过同一已安装插件身份发现 SWF 技能；全局和项目规则明确引用插件命名空间；旧的全局与项目技能投影不再作为运行入口；现有 Trio 三文件任务、授权边界、回滚备份及核心工作流保持可用。仓库可保留带清楚归档标记的旧实现及 Git 历史，但不能继续把旧包当作当前安装入口。

2026-09-25 的基线：私有 `v2.0.1+codex.20260925230000` 已安装启用；私有仓库目前只有发布包快照，完整规范源码/构建改动仍散在未提交的 SWF 工作区（见 issue #205）。全局 `~/.codex/AGENTS.md` 与项目 `AGENTS.md` 字节相同；项目未启用插件受管策略，项目 `.agents/skills` 五个 Trio/ChiefOps 入口与插件对应文件相同且同时可见。CLI 提示预览在隔离的“仅插件”项目中少了 720 个 developer 文本字符和 497 个 user 上下文字符；这不是计费 token 或行为等价证据。仓库投影测试仍要求本地 `AGENTS.md` 和 `.agents/skills` 输出。PR #203 是文档 PR，仍受 `dev` 非作者批准规则约束；不要把它的合并当成运行迁移完成。

## 目标所有权

| 资产 | 迁移后规范来源 | 运行/发布角色 |
| --- | --- | --- |
| SWF 自有的 Trio、ChiefOps、规划、CLI 和可公开的技能源码 | SWF 源码仓库中已提交的 `harness/` 等路径 | 私有构建按固定提交读取；本仓库不再向日常 Codex 项目安装同名技能投影 |
| 许可尚未核验可公开再分发的内化技能、来源记录、完整包组装与发布配置 | 私有插件源码仓库中的版本化源码 | 与固定 SWF 源码提交组装、验证并发布私有插件；当前 1,028 文件包快照保留在已有 tag 下 |
| 旧 Codex 项目/全局投影及八技能包 | Git 历史及限期兼容/回滚实现 | 不参与新安装、正常同步或自动发布；兼容测试在隔离 fixture 中运行 |
| `~/.codex/AGENTS.md` | 用户全局、带可识别受管区的简短插件入口 | 通用路由只写一次，指向 `$harness-codex-plugin:trio` 和插件能力；保留其他用户规则 |
| SWF 项目 `AGENTS.md` | 项目版本控制 | 只写项目特有约束和插件启用说明，不复制全局 Trio 正文；无全局规则的干净安装仍能独立理解入口 |
| 任务三文件、MCP、凭据、Host 调度/模型证据 | 原项目和 Host | 原路径与权限不迁移，插件仅声明所需能力 |

未来更新走“各自规范源码提交 → 私有组装仓库固定输入提交与依赖 → 构建/验收 → 新版本私有 Release → 同一插件身份升级”。不编辑插件缓存，不以旧全局 skill 目录作为更新源，也不从发布快照反向维护源码。公开仓库不得提交未获公开再分发许可的内容。

## 工作包与门槛

1. **冻结与归属。** 对 `AGENTS.md`、两个全局 skill 根、SWF 项目 `.agents/skills`、Codex 已登记项目中的其他 SWF 旧入口、当前插件源/缓存、`harness/` 与 `packages/plugin-kit` 建路径清单和哈希。逐个归属当前脏工作区的改动与并行 worktree；不能证明归属的文件不移动、不删除。记录当前 CLI 提示预览、插件版本/身份、任务三文件哈希、相关自动化与代表性工作结果。保留旧版插件和原规则备份。
2. **建立可重建源码。** 把公开安全的 SWF 自有修改按路径审查后提交到公开仓库；将内化技能及其许可/来源文件移入私有仓库。私有组装固定公开提交 SHA 和私有提交 SHA，输出文件清单、来源、许可证状态、包哈希及可重建命令。从干净检出构建候选包，并与已发布版本或预期清单做内容级差异审查；未经审查的差异不得自动升级。先解决 issue #205，再宣布规范来源已闭环。
3. **解除旧运行投影耦合。** 将当前 `harness/trio/runtime-targets.json`、`projection.mjs`、安装/同步命令和测试中“Codex 必须物化到 `.agents/skills`”的假设拆为当前插件路径与只用于旧安装迁移的兼容路径。当前路径以插件发现和受管 AGENTS 策略为验收对象；旧路径只在 fixture/回滚场景验证。移除项目中五个被扫描的同名技能入口之前，先证明插件包包含它们的全部正文、引用与脚本，以及旧 CLI/自动化没有仍在读取这些路径。项目代码修改独立成可审阅 PR；不在脏 `dev` 工作区批量删除。
4. **策略切换候选。** 为全局和项目 AGENTS 分别提供 `plan/apply/status/rollback`，按原始哈希备份，遇用户修改拒绝覆盖。全局正文只保留通用插件路由；项目正文只保留本项目特有规则。禁止把受管块直接追加到现有完整旧规则之后。新安装须显式完成插件安装与策略启用，并在新会话验证；卸载先撤销策略再移除插件。迁移过程保持同一个插件 ID，禁止第二个同名 marketplace/插件身份。
5. **隔离验收。** 在干净 Container 做安装、无登录发现、独立登录后的真实模型任务、升级、降级、卸载和再安装；在复制的 SWF 项目中做项目规则切换，不碰正在进行的任务。对照旧/新运行以下必过场景：Quick 任务直接完成；Trio 正确选 dev/office/safety；PWF 三文件建立、跨会话恢复和错误绑定拒绝；授权/项目边界拒绝；真实代码修复与测试；来源支持的 Office 产物；缺 MCP 或模型能力时准确报告缺口；至少一个高频专业技能显式和隐式调用。此前 G07、C03 等未完成正向在线路径仍单列 `unverified`，不能当成通过。42 个普通入口做会话发现和依赖校验，Pen 单独做显式入口校验；关键行为样本按原 A–H 场景矩阵逐项关闭或保留明确限制。
6. **提示与成本验收。** 同一 CLI/Host、同一模型和 effort、同一任务输入分别记录旧/新 `codex debug prompt-input`、实际任务的请求数、输入/输出 token、工具调用、耗时、正确性与停止原因。静态门槛：无项目本地五技能与插件五技能同时列出；无两份相同的 Trio AGENTS 正文；没有为一次用户请求自动创建第二次模型运行。动态门槛：所有必过场景正确且权限不放宽；若成本增大，查明具体读取或调用后修正。模型调用有随机性，用重复样本和原始记录比较，不把 1,217 字符预览差直接当作计费节省或总体效率增益。
7. **本机切换与发布。** 前述门槛通过且相关 PR 满足各自分支保护后，记录源/策略/任务哈希和回滚收据；先安装并验证新插件，再替换全局/项目策略。项目中受 Git 跟踪的旧投影由已验证的代码变更移除；全局或其他项目的受管旧目录按清单、哈希和收据迁出。用全新 Codex 任务读取实际提示与执行代表性工作；保持旧插件归档、AGENTS 备份和技能备份至少跨一次正常工作周期。发布新私有版本并下载校验，README/操作说明明确规范源码、安装、升级、回滚和限制。只有确认无调用方后才清理任务自有的旧 branch/worktree；不处理并行任务资产。

## 停止与回滚

- 任一规范来源未提交、私有包来源或许可边界不明、脏文件归属不明、插件与旧文件不等价、CI/关键场景失败、提示出现重复规则/丢失技能、授权边界放宽，均停止本机切换；保留可用旧状态并记录缺口。
- 切换后失败：先恢复 AGENTS 原字节，再按迁移收据恢复受管旧技能或将同一插件身份降至已验证版本；检查三文件任务哈希和新的提示预览。恢复不覆盖切换后新增的用户文件。公开/私有远端分别使用正常 PR/Release 回退，不改写已发布 tag 或强推。
- 完成报告须分别写明：源码提交与远端 readback、私有包构建与 Release、Container 验收、本机新会话验收、成本观察、未验证能力及回滚位置。安装成功不能单独称作“功能无损”或“全局已完全迁移”。
