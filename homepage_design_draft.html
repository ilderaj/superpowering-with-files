Why it exists

Agent workflows break when every tool invents its own memory.

Local coding agents are powerful, but their instructions, hooks, skills, and planning habits drift across platforms. The harness makes the workflow explicit, portable, and auditable.

The problem is not lack of capability. It is lack of governance.

When plans live in chat, policies are copied by hand, and deep reasoning is always-on, teams pay in context bloat, hidden state, inconsistent behavior, and risky automation.

01

Policy drift

Codex, Copilot, Cursor, and Claude Code can each read different instructions unless there is one canonical source.

02

Lost task state

Long-running work needs durable files that survive interruptions, compaction, and session handoff.

03

Overloaded reasoning

Superpowers are useful, but only when a task really needs deep structured thinking.

04

Unsafe finish

Implementation, verification, docs, and release state need a reconcile step before the task is closed.

What it provides

A small operating system for agentic coding work.

Harness separates the always-on policy core from optional execution lanes, runtime services, and safety controls.

Core

Shared policy

Platform-neutral rules, templates, schemas, and skill metadata remain the source of truth.

Adapters

Native projections

Each target gets its expected files, roots, and configuration shape without manual copy-paste.

Runtime

Typed services

Status, doctor, summaries, dry-runs, approvals, receipts, and registry checks share one business layer.

MCP

Audited facade

External agents can access governed tools and resources without bypassing the harness model.
