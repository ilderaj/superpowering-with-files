# SWF Codex plugin cutover baseline (PM-01)

Captured 2026-09-25 on the Host before any runtime switch. `baseline.json` is the output of `scripts/audit-plugin-cutover.mjs` against the local SWF checkout, the active global policy, the installed `harness-codex-plugin` package and `codex debug prompt-input`. Only aggregate prompt lengths and matched entry names are retained; the full prompt is not committed.

The global and project `AGENTS.md` files have identical SHA-256. All five project-local Trio/ChiefOps skill entry files are byte-equal to their installed-plugin counterparts and appear under both local and plugin names in the prompt preview. `diff -qr` also found no difference between the full projected `trio/` and installed `skills/trio/` trees, or between projected and installed `chiefops/` trees (12 regular files total, all Git-tracked in the project). No standalone copy of those five was found in the two user-global skill roots. The installed version is `2.0.1+codex.20260925230000`.

This proves duplicated routing text and discoverable entries in the current project. It does not prove duplicate model requests, billed token waste, equivalent outcomes after removal or that all supporting files/scripts are identical. Prompt preview counts are 28,795 developer characters and 3,583 user characters; they are not token counts. The existing Trio task files, concurrent worktrees and primary dirty checkout were not changed by the audit. A pre-checkpoint hash snapshot was captured for the Trio files: task plan `1f2a739ba0e1cf5ecc54a2d10799fe7c1bdc51c7454452f09f77ff8bdc467d51`, findings `91e61bdf043433f4ef15a422140d77df7ec696aa0cf7dc3520fbac08c07059f2`, progress `cb4b3f75638abecf666bb3da2c1c47c054cbf9c01055082a9b54fc3814205d35`.

Current caller inventory shows that `harness/trio/runtime-targets.json` and `harness/trio/projection.mjs` still define `.agents/skills` as a Codex projection target. `packages/plugin-kit/src/platform-contracts.mjs` imports that projection, while install/upgrade, projection, routing, permissions and package tests assert the old materialized paths. This is why removing the tracked local skill tree now would make the repository contract fail, even though the installed plugin has byte-equal copies. The public `packages/plugin-kit` implementation has other uncommitted changes in the primary checkout; their ownership and redistribution scope must be reviewed file by file before source promotion.

On 2026-09-26 the Codex app listed eight saved local projects. A read-only check of each root `AGENTS.md` and the five exact local Trio/ChiefOps entry paths found the old entry set only in SWF. Three other saved projects had their own `AGENTS.md`, none with the old Trio header or plugin namespace; four had no root `AGENTS.md`. This is a point-in-time scan of registered roots, not a claim about every nested checkout or future project.

PM-01's baseline and path ownership inventory are complete for the listed roots. Recheck plugin/policy/task hashes immediately before PM-06; the baseline is not a standing deletion permit.
