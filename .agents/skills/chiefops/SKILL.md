# ChiefOps

ChiefOps is governance-only. When explicitly invoked for intake, route through Trio before choosing execution: quick work stays direct with no mandatory planning or Linear issue; tracked work creates or restores the three planning files. Use governed delegation only when selected; direct tracked work needs no ChiefOps check-in to complete its own verification. The Trio remains the sole durable task authority; the Host owns lifecycle, continuation, permissions, and authenticated execution evidence.

For tracked work, restore the bound task's three planning files at entry or recovery. Choose a concrete bounded slice and record decisions, evidence, blockers, and acceptance at milestones. Honor existing authorization within its scope; clarify only missing material decisions or authorization.

Reuse optional `linear-work-control` for human-facing checkpoints; reuse a binding or onboard only when human visibility, a decision, or handoff warrants it. For authorized writes, pass the workspace guard and look up an existing issue before creating one; retain one issue and status comment per task. A missing or disabled binding keeps work local-only unless onboarding is selected. Store `reports/linear/<task-id>/linear.json` as non-authoritative external metadata; keep authoritative blockers in `progress.md` and decisions/evidence in the Trio. Delegate legacy binding/CLI reads to the compatibility helper; create no fourth authority or metadata inside the three-file task directory.

For a tracked task that can run unattended, intake ends with an explicit night-queue decision rather than silence, because `nightly` is the only switch the night executor reads: absence means not scheduled, and no run infers intent from wording, priority, or a time window. Recommend the label only when the slice is bounded, acceptance is written, no human decision is pending, and its edit surface does not overlap other night work; otherwise leave it off and name the condition that would earn it. Writing it schedules an unattended local run, so state the recommendation and its reason at intake, and let the human confirm, decline, or edit the label — removing it removes the task from tonight. Ask through whatever decision surface the Host exposes: a structured question when one exists, otherwise a single recommendation line the human answers in place. Write the label only after that answer; silence leaves the task out of tonight. External or destructive steps stay human-gated whether or not the label is present.

For day/night work, perform a local-first readiness audit of the bound Trio, authorization, dependencies, blockers, and current evidence. Reuse unchanged evidence; refresh only changed or unresolved checks. Select a bounded ready slice with no overlapping edits; leave blocked work with its exact resume condition. A human handoff records completed work, validation, blockers, the decision needed, next action, and resume condition. The Host owns scheduling and continuation; distinguish configured, triggered, and observed runs, and never infer authorization from a time window.

For GitHub-bound delivery, record repository, PR, current head SHA, required checks, applicable review gates, and the observed merged or closed result. A changed head invalidates head-bound proof. Satisfy the task's delivery criteria: local validation is not proof of merge, deployment, or adoption; a closed-unmerged PR does not prove delivery. Reconcile evidence locally before publishing a checkpoint; a PR alone does not authorize a monitor or external write.

For local archive, reconcile validation, applicable acceptance, human gates, and required delivery evidence before recording `Status: closed`, `Archive Eligible: yes`, and a `Close Reason`; use the existing Chief-owned archive path. Linear `Done` requires the completion gate; Linear auto-archive offers no manual archive action. Unfinished projects, open parents, open sub-issues (including those in other projects), and active cycles can block or delay archive; closed items must remain inactive for the full configured auto-archive period and project/cycle eligibility must also be satisfied. Never promise immediate archive or quota release, or delete issues to simulate archive. See [Linear's archive rules](https://linear.app/docs/delete-archive-issues). Codex task archive is a separate authorized Host action; verify each archive outcome independently.

For dispatch, frozen scope, worker approval, or recovery, read [delegated execution](references/delegated-execution.md). For an explicitly bound PR monitor, load dev's `references/pr-feedback.md`; it owns read-only observation, current-head gates, and terminal lifecycle.

Accept a delegated candidate only after independent review of relevant evidence and Trio writeback. A selected human gate remains binding. Return acceptance or a blocker with the exact resume condition. This companion is not a runner, scheduler, registry, cross-thread goal controller, or fourth task-state surface, and sets no model-specific execution policy.
